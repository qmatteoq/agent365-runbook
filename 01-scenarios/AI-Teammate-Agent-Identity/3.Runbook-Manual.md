# Step-by-step guide: AI Teammate with agent identity (manual path)

> **Scenario**: Publishing a custom-code agent as a Microsoft Agent 365 AI Teammate / Autopilot
> **Platform**: Microsoft Agent 365, Microsoft Entra Agent ID, Teams and OpenTelemetry
> **Worked examples**: .NET Agent Framework, Python + LangChain, Node.js + LangChain
> **Target readers**: Agent developers and tenant administrators
> **Last updated**: September 2026

## Introduction

We're going to register our custom-code agent as an AI Teammate and connect its activity to Microsoft 365 reporting. We'll keep its working model provider, tools and application logic, add the required identity and telemetry integration, then verify an approved instance in Teams. We can do this with the CLI and manual code edits; no coding assistant, installed skill or Copilot Studio project is required.

Start with our agent's code and deployment. The Microsoft Learn agents linked below are optional educational examples for practising the changes in a separate application. We don't need to clone them or adopt their model provider, and they aren't production templates.

An AI Teammate has its own agent identity and agent user account. A person who sends it a message is the caller, while the teammate accesses delegated services as its agentic user. This is agentic-user authentication, not human on-behalf-of authentication and not application-only S2S. Model authentication remains separate from the channel and observability token flows.

### Why there is no Azure Bot resource

This AI Teammate registration path does not require an Azure Bot resource or an Azure Bot OAuth connection. `a365 setup all --aiteammate --m365` registers our public message endpoint on the blueprint through the Microsoft 365 control plane. The Teams Developer Portal calls that endpoint the **Notification URL**. Keep any existing Bot resources that serve other channels; this walkthrough doesn't replace those integrations.

Our application needs a Microsoft 365 Agents SDK channel host that can authenticate incoming activities, pass the authenticated activity to our agent and send channel replies. Reuse that host if it exists. If the application only exposes a model API or a different messaging protocol, add the appropriate [Agents SDK hosting adapter](https://learn.microsoft.com/microsoft-365/agents-sdk/quickstart) around the existing agent before registration. The examples below assume an `AgentApplication` and use `/api/messages`; neither that file layout nor that route name is required for our own host.

The blueprint credentials authenticate the channel connection and support the agentic token chain. They are different from the runtime instance identity that we put on telemetry:

| Value | Where we get it | Where it belongs |
| --- | --- | --- |
| Blueprint application ID | `agentBlueprintId` in `a365.generated.config.json` | Channel connection client ID, inbound audience, blueprint roll-up |
| Runtime agent instance application ID | `GetAgenticInstanceId()`, `get_agentic_instance_id()` or `getAgenticInstanceId()` on an authenticated activity | `gen_ai.agent.id`, the export URL and the token-cache key |
| Agent user's directory object ID | The activity's agentic-user accessor | `microsoft.agent.user.id` |
| Human caller's directory object ID | The sender's `aadObjectId` | `user.id` on the invocation |

In the Node SDK's `AgentDetails`, `agentId` is the runtime instance application ID and `agentAUID` is the agent user's directory object ID. We'll use those explicit identity names throughout the guide. Neither field takes the blueprint ID.

This helper calls `identity.IsTenantIdIssuerValid()`, which is unavailable in Agents SDK 1.7.123. For that SDK version, preserve tenant validation by replacing `!identity.IsTenantIdIssuerValid()` with `!HasConsistentTenantIssuer(identity)` in `AspNetExtensions.cs`, then adding this method inside its `AspNetExtensions` class:

```csharp
private static bool HasConsistentTenantIssuer(System.Security.Claims.ClaimsIdentity identity)
{
    if (!Guid.TryParse(identity.FindFirst("tid")?.Value, out var tenantId) ||
        !Uri.TryCreate(identity.FindFirst("iss")?.Value, UriKind.Absolute, out var issuer) ||
        issuer.Scheme != Uri.UriSchemeHttps)
    {
        return false;
    }

    var segments = issuer.AbsolutePath.Split('/', StringSplitOptions.RemoveEmptyEntries);
    return (segments.Length == 1 ||
            (segments.Length == 2 && segments[1] == "v2.0")) &&
        Guid.TryParse(segments[0], out var issuerTenantId) &&
        tenantId == issuerTenantId;
}
```

This checks that the validated Entra issuer's tenant path agrees with the token's `tid` claim. The helper validates its allowed issuer list before this callback runs; the method does not replace issuer, signature or audience validation. It permits the documented Microsoft channel service tenants as well as the configured agent tenant. Use the corresponding SDK-supported validation when adapting this helper to another version.

_LOCK = threading.Lock()


def resolve_token(agent_id: str, tenant_id: str) -> str:
    with _LOCK:
        entry = _TOKENS.get((agent_id, tenant_id))
        if entry and entry[1] > time.time() + 60:
            return entry[0]
        _TOKENS.pop((agent_id, tenant_id), None)
    raise RuntimeError("No valid observability token is cached for this agentic instance and tenant.")


def cache_token(agent_id: str, tenant_id: str, token: str) -> None:
    payload = token.split(".")[1]
    claims = json.loads(base64.urlsafe_b64decode(payload + "=" * (-len(payload) % 4)))
    expiry = float(claims["exp"])
    if expiry <= time.time() + 60:
        raise ValueError("Observability token is expired or too close to expiry.")
    with _LOCK:
        now = time.time() + 60
        for key in [key for key, value in _TOKENS.items() if value[1] <= now]:
            del _TOKENS[key]
        _TOKENS[(agent_id, tenant_id)] = (token, expiry)

    question: str,
    research: Callable[[], Awaitable[str]],
) -> None:
    if not context.activity.is_agentic_request():
        await context.send_activity(await research())
        return

    activity = context.activity
    agent_id = activity.get_agentic_instance_id()
    tenant_id = activity.get_agentic_tenant_id()
    agent_user_id = activity.get_agentic_user()
    blueprint_id = os.environ.get("AGENT365_BLUEPRINT_ID", "")
    caller_id = getattr(activity.from_property, "aad_object_id", None)
    conversation_id = getattr(activity.conversation, "id", None)
    try:
        for value in (agent_id, tenant_id, agent_user_id, blueprint_id, caller_id):
            UUID(str(value))
    except (ValueError, AttributeError) as error:
        raise ValueError(
            "The agentic turn needs valid instance, tenant, agent-user, blueprint and human-caller IDs."
        ) from error
    if tenant_id.lower() != os.environ.get("AGENT365_TENANT_ID", "").lower():
        raise ValueError("The agentic activity tenant does not match this deployment.")
    if not conversation_id or not activity.channel_id:
        raise ValueError("The agentic activity needs a conversation ID and channel.")
    endpoint = urlparse(os.environ.get("AGENT365_ENDPOINT", ""))
    if endpoint.scheme != "https" or not endpoint.hostname:
        raise ValueError("AGENT365_ENDPOINT must be an absolute HTTPS URL.")
    port = endpoint.port if endpoint.port is not None else 443
    if port <= 0:
        raise ValueError("AGENT365_ENDPOINT must use a valid HTTPS port.")

    handler = agent_app.auth._resolve_handler("AGENTIC")
    response = await handler.get_agentic_user_token(context, [SCOPE])
    if not response or not response.token:
        raise RuntimeError("The agentic handler returned no observability token.")
    cache_token(agent_id, tenant_id, response.token)
    resolve_token(agent_id, tenant_id)

    agent_name = os.environ.get("AGENT365_NAME", "LearnTeammate")
    channel = activity.channel_id
    agent = AgentDetails(
        agent_id=agent_id,
        agent_name=agent_name,
        agent_description="Researches Microsoft documentation with Microsoft Learn MCP.",
        agentic_user_id=agent_user_id,
        agent_blueprint_id=blueprint_id,
        tenant_id=tenant_id,
    )
    caller = CallerDetails(user_details=UserDetails(
        user_id=caller_id,
        user_name=getattr(activity.from_property, "name", None),
        user_client_ip="0.0.0.0",
    ))
    request = Request(
        content=[question],
        session_id=conversation_id,
        conversation_id=conversation_id,
        channel=Channel(name=channel),
    )
    clean_context = otel_context.attach(otel_context.Context())
    try:
        with (
            BaggageBuilder()
            .tenant_id(tenant_id)
            .agent_id(agent_id)
            .agent_name(agent_name)
            .agent_blueprint_id(blueprint_id)
            .agentic_user_id(agent_user_id)
            .conversation_id(conversation_id)
            .session_id(conversation_id)
            .channel_name(channel)
            .user_id(caller_id)
            .user_client_ip("0.0.0.0")
            .set_pairs({"server.address": endpoint.hostname, "server.port": str(port)})
            .build()
        ):
            with InvokeAgentScope.start(
                request=request,
                scope_details=InvokeAgentScopeDetails(
                    endpoint=ServiceEndpoint(hostname=endpoint.hostname, port=port)
                ),
                agent_details=agent,
                caller_details=caller,
            ) as invocation:
                try:
                    invocation.record_input_messages([question])
                    answer = await research()
                    invocation.record_output_messages([answer])
                    with OutputScope.start(
                        request=request,
                        response=Response(messages=[answer]),
                        agent_details=agent,
                    ):
                        await context.send_activity(answer)
                except Exception as error:
                    invocation.record_error(error)
                    raise
    finally:
        otel_context.detach(clean_context)
```

The exporter reads a synchronous dictionary while the turn acquires tokens asynchronously. The lock protects those two callers, and the resolver raises an error for a missing or expired token. Invalid agentic identity, configuration or token acquisition stops the turn before model execution and reaches the existing application error handler. The plain response remains available only for non-agentic turns.

The JWT payload is decoded only to schedule expiry for an already acquired token; it does not authenticate an incoming request, and we don't log its contents. Attaching a fresh context before building baggage makes the invocation a root. The `finally` block restores the incoming context after success or failure.

Python's built-in `AgenticTokenCache.get_observability_token` is asynchronous, so passing it straight to a synchronous resolver returns a coroutine instead of a bearer token. The example caches the token string for that reason. `_resolve_handler` is a private Agents SDK 1.2.0 method; this code depends on that version's contract. For a different SDK version, use its supported authorization access path and confirm the token-return contract. The handler's `get_agentic_user_token` requests the observability scope directly without requiring Graph-scoped sign-in.

const observabilityScope =
    "api://9b975845-388f-4429-889e-eab1ef63949c/Agent365.Observability.OtelWrite";
const guid = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

function resolveToken(agentId: string, tenantId: string): string {
    const token = AgenticTokenCacheInstance.getObservabilityToken(agentId, tenantId);
    if (!token) {
        throw new Error("No valid observability token is cached for this agentic instance and tenant.");
    }
    return token;
}

    a365: {
        enabled: true,
        enableObservabilityExporter: true,
        tokenResolver: resolveToken,
        useS2SEndpoint: false,

export async function runObserved(
    context: TurnContext,
    authorization: AuthorizationLike,
    question: string,
    research: () => Promise<string>,
): Promise<void> {
    const activity = context.activity;
    if (!activity.isAgenticRequest()) {
        await context.sendActivity(await research());
        return;
    }

    const agentId = activity.getAgenticInstanceId();
    const tenantId = activity.getAgenticTenantId();
    const agentUserId = activity.getAgenticUser();
    const blueprintId = process.env.AGENT365_BLUEPRINT_ID ?? "";
    const callerId = activity.from?.aadObjectId ?? "";
    const conversationId = activity.conversation?.id ?? "";

    try {
        endpoint = new URL(process.env.AGENT365_ENDPOINT ?? "");
    } catch (error) {
        throw new Error("AGENT365_ENDPOINT must be an absolute HTTPS URL.", { cause: error });
    }
    if (endpoint.protocol !== "https:" || !endpoint.hostname ||
        (endpoint.port !== "" && Number(endpoint.port) <= 0)) {
        throw new Error("AGENT365_ENDPOINT must be an absolute HTTPS URL.");
    }
    if (![agentId, tenantId, agentUserId, blueprintId, callerId].every(
        (value) => typeof value === "string" && guid.test(value),
    )) {
        throw new Error(
            "The agentic turn needs valid instance, tenant, agent-user, blueprint and human-caller IDs.",
        );

        throw new Error("The agentic activity tenant does not match this deployment.");

        throw new Error("The agentic activity needs a conversation ID and channel.");
    }

        throw new Error("The validated activity is missing an agentic identity.");

    const channel = activity.channelId;
    const agent: AgentDetails = {
        agentId,
        agentName,
        agentDescription: "Researches Microsoft documentation with Microsoft Learn MCP.",
        agentAUID: agentUserId,
        agentBlueprintId: blueprintId,
        tenantId,
    };

        content: [question],
        conversationId,
        sessionId: conversationId,
        channel: { name: channel },
    };
    await otelContext.with(ROOT_CONTEXT, async () => {
        const baggage = new BaggageBuilder()
            .tenantId(tenantId)
            .agentId(agentId)
            .agentName(agentName)
            .agentBlueprintId(blueprintId)

            .sessionId(conversationId)

                    userId: callerId,
                    userName: activity.from?.name,
                    callerClientIp: "0.0.0.0",

                    const answer = await research();
                    invocation.recordOutputMessages([answer]);

                    try {
                        await output.withActiveSpanAsync(() => context.sendActivity(answer));

                    }
                });
            } catch (error) {

        });

    "ExecuteToolBySDK", "ExecuteToolByGateway", "ExecuteToolByMCPServer")
| extend Details = parse_json(RawEventData)
| where tostring(Details.TargetAgentId) == instanceAppId
    or tostring(Details.AgentId) == instanceAppId
    or tostring(column_ifexists("AgentId", "")) == instanceAppId
| project Timestamp, ActionType,
    AgentName = coalesce(tostring(Details.TargetAgentName), tostring(Details.AgentName)),
    ConversationId = coalesce(
        tostring(Details.ConversationId),
        tostring(Details.CopilotEventData.ConversationId)),
    Details
| order by Timestamp desc
```

The query checks the operation-specific agent-ID fields described by the attribute reference. Filter on the runtime instance application ID, not the blueprint. Allow for indexing delay and verify the time range before treating an empty result as an ingestion failure.

### Step 4-3. Check the admin center

1. Open [Microsoft 365 admin center](https://admin.cloud.microsoft), select **Agents** > **All agents**, and locate the approved instance.
2. Open **Activity** and find the conversation created in Step 4-1.
3. Verify that the teammate's activity rolls up to the correct blueprint and that the human caller is a separate dimension.
4. If auditing is part of the rollout, have the administrator confirm the organization's [Purview auditing configuration](https://learn.microsoft.com/purview/audit-log-enable-disable) as well.

The activity view needs a root invocation and conversation ID. We may see Defender rows while the admin-center view remains empty if that invocation is missing or unusable, so check both views rather than relying on an HTTP `200`.

### Step 4-4. Work through failures by layer

Use the [cross-scenario troubleshooting guide](../../03-references/Troubleshooting.md) for the diagnostic sequence and SDK-specific checks. It also covers approved-instance provisioning and the difference between export acceptance and visible activity.

| Symptom | What we check |
| --- | --- |
| Public anonymous POST reaches the model | Disable the affected route's public exposure and repair its channel policy without replacing unrelated application security. In the samples, check .NET authentication/middleware and `RequireAuthorization`, Python `ANONYMOUS_ALLOWED=false`, or Node connection configuration and production mode. |
| Teams can't reach the process | Check our deployment's ingress, route and blueprint **Notification URL**. For a local sample, also check the port and tunnel. Re-register a changed endpoint with the endpoint-only command. |
| Blueprint appears but no instance can be requested | Check activation, the pilot audience, tenant feature enablement and available instance licences. |
| Request remains pending | The administrator must approve it in **Requested agents**; republishing doesn't approve an instance. |
| Optional .NET implementation can't find `AddAgentAspNetAuthentication` | It is in the downloaded `AspNetExtensions.cs`, not an SDK package. Confirm the file is in the sample project and the JWT dependencies restored. |
| Credentials aren't available in the host | Check our production secret provider and identity permissions. Only the local .NET sample uses `A365_LOCAL_RUN=true` with `AddUserSecrets` in Production. |
| .NET export has no token | Confirm the configured handler and agentic sign-in route agree. In the sample, check `AgenticAuthHandlerName` and `autoSignInHandlers`. |
| Python reports no service connection | Check the host's connection manager and configured connection name. The sample uses `CONNECTIONS__SERVICE_CONNECTION__SETTINGS__*`. |
| Python says the auth handler is unrecognized | Match the actual handler name and SDK configuration schema. The 1.2.0 example uses `AGENTIC`, with `TYPE` under `HANDLERS__AGENTIC`, not `SETTINGS`. |
| Python resolver returns a coroutine or has no token | Acquire the token during the turn and cache `TokenResponse.token`; the exporter must call a synchronous resolver. |
| Node logs an undefined app ID | Load the application's configuration before Agents SDK modules. The local sample does this through `src/env.ts` and its bootstrap. |
| Node has invocation spans but no framework children | Check the instrumentation for our actual framework and its loader/bootstrap requirements. For the LangChain sample, use the loader-enabled `npm start`, not `tsx src/main.ts`; retain one distro initialization. |
| A typing activity gets `400` on an agentic turn | Suppress typing on that route while preserving supported behavior elsewhere. The examples use .NET/Node guards and Python `start_typing_timer=False`. |
| Non-agentic local tests produce no tenant telemetry | Expected: they contain no approved agentic identity. Test the actual teammate through Teams. |
| An agentic turn returns the application's error reply before task execution | Check the required instance, tenant, agent-user, blueprint and caller IDs, endpoint configuration and observability token. An invalid identity or missing token must fail; don't bypass that check with an uninstrumented success reply. |
| Invocation has an HTTP parent or child identity is missing | Start the invocation in a clean context and propagate the validated identity to child spans. In the .NET example, register the backfill processor before the distro and retain both explicit activity-source subscriptions. |
| `AADSTS65001` or consent errors | Compare the requested scope and resource audience with the approved instance grants. Don't silently fall back to a human or app-only token. |
| Export gets `401` | Check token expiry and the observability audience; a model or messaging token won't work. |
| Export gets `403` | Check scope consent, tenant entitlement, instance ID/token agreement and delegated endpoint selection. |
| Export succeeds but no activity appears | Check indexing, licences, root invocation, conversation ID, required attributes and the reporting principal. |
| Work IQ manifest exists but an intended tool is unavailable | Check runtime registration, resource permissions and per-turn authentication in our application. The optional examples only configure selection/grants, not runtime Mail tools. |
| A singleton tool client can access another instance's data | Stop that integration and fix tenant/instance ownership of tokens, clients, tools and memory before continuing. |

Before sharing diagnostics, remove client secrets, authorization headers, access tokens and sensitive prompts. The blueprint ID, instance ID, timestamp, operation name and sanitized status code are usually enough to identify which layer failed.

## Wrapping up

We've registered our agent as an AI Teammate, connected its authenticated channel endpoint and attributed its work to the runtime instance. The blueprint holds the channel registration, while the agentic user supplies the delegated identity for observability. The application's model provider and its authentication remain independent choices.

Keep the application's production hosting, secret management, session ownership and tool integrations, and address any gaps found during verification. For unattended work, validate the actual event handlers and durable execution path as well as the identity and permissions they use. Work IQ capabilities depend on both grants and runtime integration, not publication alone.

If we used an educational sample, stop its local process and tunnel when finished and retire any practice instances and licences that are no longer needed. Keep our real deployment on its normal operating lifecycle. The [overview](1.Overview.md), [architecture](2.Architecture.md), [token-chain reference](../../02-patterns/The-Three-Token-Chains.md) and [official attribute reference](https://learn.microsoft.com/microsoft-agent-365/developer/observability-attribute-reference) provide further detail on the identity and reporting model.
